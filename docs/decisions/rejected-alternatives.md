# 却下済み案と理由

リリース前品質改善キャンペーン（統括 issue #11、Fusionパネル記録 `.fusion-runs/`、grillingセッション）で検討し、採らないと決めた案。再提案する場合は、ここに記した却下理由の前提が失効したことを示すこと。

不変条件の優先順位: **決定性 ＞ 宣言表面の忠実性 ＞ 利便性**

| 却下案 | 理由 |
|---|---|
| streaming 介入 | 決定性のため MVP design で却下済み。全行 materialize が決定的障害適用の前提 |
| 完全 DB-API 互換 | 目標は「宣言した対応表面内での忠実性」であり、互換表面の網羅ではない |
| row_factory 対応 | 行は tuple 正規化を維持。決定性＞忠実性を適用した明示的不忠実（backend-faithful-surfaces の ADR-001 に記録） |
| max_intervention_rows 既定での切り詰め | 上限は「介入してよい行数」でありメモリ・取得上限ではない。結果の無断改変は決定性契約と正直さに反する（W1-c で確定） |
| 不安定 fallback fingerprint | 再現不能な決定キーは決定性契約を破る |
| occurrence 辞書の eviction | 途中で忘れる occurrence は同一seed・同一SQL列の再現性を破る |
| 計測先行のparser導入ゲート（`expand-dolly-faults` D12） | テスト専用ツールには計測対象となる実アプリcorpusが構造的に存在せず、ゲート維持は無期限先送りと同義。sqlglotへ直行し、導入後も残るUNKNOWN率の事後検証（`unknown_sql`統計、W6-3）へ置換する |
| C1: Python下限（`>=3.12`）の引き下げ | 設計実験フェーズでは動機が薄く、sqlite3の3.12+挙動前提の回帰確認とCIマトリクス整備という検証コストに見合わない |
| 犬命名の技術名への置換 | プロダクトのアイデンティティ。挙動仕様と干渉しない |
| 本番向け常駐監視化 | テスト専用障害注入ツールという立ち位置に反する（ジョークツールからの移行先はテスト用途であって本番運用ではない） |
