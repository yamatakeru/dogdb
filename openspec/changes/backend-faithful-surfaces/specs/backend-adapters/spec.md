# backend-adapters 差分 — conformance契約の介入コア一致への再定義

## MODIFIED Requirements

### Requirement: 共通適合テストスイート
両アダプタは同一のシナリオスイート（スキーマ作成、データ投入、各障害の発火と検証）を通過しなければならない（MUST）。バックエンド間の一致要件は介入コアに限定される（SHALL）: 同一seed・同一session_id・同一障害設定・同一SQL列に対する障害イベント列（fault、decision_key、outcome）、decision、および論理結果への障害適用結果は両バックエンドで一致しなければならない（MUST）。論理結果の行順序の一致は、ORDER BY等で行順序が決定的に定まるクエリに限って要求され、それ以外のクエリでは行の多重集合として比較しなければならない（SHALL）。公開表面の挙動（execute の返り値型、結果取得の入口、コンテキストマネージャ意味論）はバックエンド間の一致対象ではなく（SHALL NOT）、各バックエンドのネイティブ表面との同型性で検証される（SHALL）。この一致要件はバックエンドの自然な行順序に依存しない — イベントは行値を含まず、行位置は決定キーのみから導出されるため、ORDER BYのないクエリで両バックエンドが異なる順序の行を返してもイベント列は同一になる。

#### Scenario: ドリーはDBを差別しない
- **WHEN** 共通適合スイートを同一seedでDuckDBとSQLiteに対して実行する
- **THEN** 両者のイベントログは診断用タイムスタンプとbackend識別子を除いて一致する

#### Scenario: 表面が分岐しても介入コアは一致する
- **WHEN** 同一seed・同一session_id・同一障害設定・同一SQL列を、DuckDBプロキシ（接続レベルfetch）とSQLiteプロキシ（カーソル経由fetch）というそれぞれの表面で実行する
- **THEN** 障害適用後の論理結果（隠蔽・値変異を含む行の多重集合。ORDER BY等で順序が定まるクエリは行順序も）と障害イベント列は両バックエンドで一致する
